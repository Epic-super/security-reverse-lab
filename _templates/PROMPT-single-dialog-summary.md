# PROMPT · 单对话价值提炼（脱敏优先）

> **这个提示词解决什么**
>
> 你有一个对话（脱壳过程 / 一次挖洞 / 协议还原 / 排查线上问题）。
> 里面藏着 valuable 的部分，但混着：你的猜测、走错的弯路、真实域名、真实 token、真实内部信息。
>
> 这个提示词做两件事：
> 1. **提炼**：把对话里真正有复用价值的东西抽出来 —— 方法、原理、判断依据、可复现步骤
> 2. **脱敏**：把一切能指向你本人/你雇主/你的目标的东西替换掉，并且**列一张清单告诉你改了什么**
>
> **核心原则**：**宁可少写，不可泄漏。** 脱敏不是最后一步，是写作时的同步动作。

---

## 使用方式

**方式 A（推荐）**：直接贴在**那个对话的末尾**。AI 已有全部上下文，能准确区分"哪句是关键发现"和"哪句是废话"。

**方式 B**：开新对话，把整个对话复制进去，再贴这段。

## 提示词正文（整段复制）

```text
把上面这个对话整理成一份**可复用的技术沉淀**。目标读者是刚入门的小白，
他们要能照着做一遍，并且理解每一步背后的原理。

═══════════════════════════════════════════════════════════
【第一原则：脱敏优先，且必须显式报告】
═══════════════════════════════════════════════════════════

我在做技术记录，但这个对话里有真实信息，不能直接公开。

**你必须主动替换下列内容，并保持全文一致**（同一个东西必须用同一个占位符）：

| 类别 | 替换成 | 例子 |
|---|---|---|
| 真实域名 / 主机名 | `TARGET` / `TARGET_SUBDOMAIN` / `example.com` | `admin.corp-internal.com` → `TARGET_SUBDOMAIN` |
| 真实 IP | `TARGET_IP` | `10.13.37.42` → `TARGET_IP` |
| 端口 | 保留真实端口，或 `TARGET_PORT` | |
| URL 路径里含业务信息 | 抽象化 | `/api/v2/内部系统/订单` → `/api/v2/ENDPOINT` |
| Token / API Key / Cookie / Session | `<REDACTED>` | `ghp_xxx` → `<REDACTED>` |
| 密码 / 口令 | `<REDACTED>` | |
| 真实人名 | `USER_A` / 角色名 | 张三 → `USER_A` |
| 邮箱 | `<REDACTED_EMAIL>` | |
| 公司名 / 组织名 | `ORG` | |
| 产品内部代号 / 项目代号 | `PROJECT` | |
| 文件路径中的用户名 | `USER_HOME` | `C:\Users\真实名\` → `USER_HOME\` |
| 真实内部系统名 | `INTERNAL_SYSTEM` | |
| 数据库 / 表名 | `DB_NAME` / `TABLE_NAME` | |
| 客户 / 租户标识 | `TENANT` | |

**保留**（这些是技术的核心，不是隐私）：
- 漏洞类型、函数名、类名、API 名、协议名、错误码
- 参数名、字段名、偏移量、字节值
- 工具名与版本、命令本身
- 原理、机制、判据

**不确定某个信息算不算隐私时，替换掉。** 宁可多脱一点。

**对话里如果存在以下内容，必须主动指出并单独提示我，不要写进文章**：
1. 真实凭据、密钥、私钥、token
2. 未公开的漏洞细节 + 漏洞方的名称（如果还没修复或还没提交）
3. 内部系统架构、员工信息、业务数据
4. 任何可能让我或我的雇主承担责任的操作细节
5. 你的身份线索（"我朋友的公司"、"我之前那个项目"）

把这些单独列成 **「⚠️ 需要我确认」** 一节，让我决定怎么处理。

═══════════════════════════════════════════════════════════
【第二原则：只提炼有复用价值的，去掉噪音】
═══════════════════════════════════════════════════════════

**必须保留**（这是"价值"）：
- **方法论**：下次遇到同类问题，第一步该做什么
- **原理**：为什么这么做有效，底层机制是什么
- **判据**：看到什么现象说明这条路对了 / 错了
- **可复现步骤**：别人照着能跑一遍
- **踩过的坑**：现象 → 原因 → 解决（这是对话里最值钱、最常被浪费的部分）
- **工具技巧**：省时间、少走弯路的用法

**必须丢掉**（这是"噪音"）：
- 寒暄、试错时的随机尝试（除非它本身是个有价值的教训）
- 与结论无关的中间输出（几百行日志里挑关键那几行）
- 对话中的犹豫、闲聊、重复确认
- 你的个人信息

**如果对话里没有真正的技术发现**（比如只是环境配置、只是查资料），
就如实说明"本次对话的价值是 XX"，不要硬凑成一篇技术文章。

═══════════════════════════════════════════════════════════
【输出结构】
═══════════════════════════════════════════════════════════

# <标题>

> **一句话结论**：<这次对话到底解决了什么问题>

> **⚠️ 脱敏提示**：本文中 `TARGET`、`TARGET_IP`、`<REDACTED>` 等均为占位符，
> 原文见 <你所在的位置>。

## 0. 这次对话解决了什么
   - 问题：
   - 结论：
   - 下次遇到同类问题，第一步该做什么：   ← 这一条单独列出，最有价值

## 1. 前置知识
   只讲必需的，每个术语一句话大白话解释（首次出现保留英文原文）

## 2. 环境
   - 系统 / 工具及版本 / 依赖 / 目标
   - 验证方式

## 3. 原理
   用大白话讲机制。必须有：
   - 涉及的文件格式 / 内存结构 / 协议报文的字段布局（用表格）
   - 关键判断条件从哪来（算法算的？硬编码的？）
   - 为什么作者/系统会这样设计

## 4. 操作步骤
   每一步四件套：
   ① 这一步干什么用的
   ② 在哪执行（目录 / 前提）
   ③ 命令 / 操作
   ④ 预期输出 + **这步证明了什么**

   关键判断点用【关键】标出。

## 5. 结果验证
   怎么确认成功了；失败时的排查表（现象 → 原因 → 处理）

## 6. 踩过的坑
   表格：现象 | 原因 | 解决
   （对话里的弯路写这里，不要省）

## 7. 方法论沉淀
   - 可复用的检查清单（checklist）
   - 关键判断信号（看到 X 就说明 Y）
   - 工具技巧

## 8. 延伸
   - 这个技术还能用在哪
   - 换个场景会怎么变

## 9. 复现清单
   逐步 checkbox，每格写预期现象
```

## 变体：只做脱敏，不改内容

> 对话已经写成文章了，只想让它能公开。

```text
对上面的文章做脱敏改写。

要求：
1. 逐项替换：真实域名→TARGET、IP→TARGET_IP、token/cookie/key/密码→<REDACTED>、
   人名→USER_A、公司→ORG、邮箱→<REDACTED_EMAIL>、
   文件路径中的用户名→USER_HOME、内部系统名→INTERNAL_SYSTEM、
   数据库/表名→DB_NAME/TABLE_NAME、业务接口路径→抽象化。
2. **保持文章结构和行文不变**，只做替换和必要的语序调整。不要重写、不要精简。
3. 同一个东西全文用同一个占位符。
4. 替换后通读一遍，检查有没有"换了 A 但后文还在说 B"的残留，以及
   替换后句子是否还通顺。
5. 输出：
   - 完整改写后的文章
   - 替换对照表（原文 → 替换为 → 类别）
   - 「仍需人工确认」清单：那些你拿不准是不是敏感的，标出来让我自己看
6. 不要改技术内容。如果发现技术内容有错，单独列在最后的「附：发现的技术问题」里，不要直接改。
```

## 附：自己检查用的小抄

发文章前自己扫一遍：

```bash
# 凭据
grep -rInE "(ghp_[A-Za-z0-9]{20,}|github_pat_[A-Za-z0-9_]{20,}|AKIA[0-9A-Z]{16}|AIza[0-9A-Za-z_-]{30,}|-----BEGIN [A-Z ]*PRIVATE KEY-----)" . --exclude-dir=.git

# 邮箱
grep -rInE "[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}" . --exclude-dir=.git

# 内网 / 真实 IP
grep -rInE "\b(10\.[0-9]{1,3}|172\.(1[6-9]|2[0-9]|3[01])|192\.168)\.[0-9]{1,3}\.[0-9]{1,3}\b" . --exclude-dir=.git

# 真实业务域名（排除 example.com / github.com / 常见白名单）
grep -rInE "https?://[a-z0-9.-]+\.(com|cn|net|io|top|xyz|cc|vip)" . --exclude-dir=.git
```

**Windows 用户名路径**：检查 `C:\Users\<你的名字>` 是否出现在示例里。

**一句话总结这个提示词的逻辑**：
**先把"不能说的"变成"看不见的"，再从剩下的对话里挑出"下次还用得上的"。顺序不能反。**
